GPR-Studio — Advanced GIS and Ground-Penetrating Radar Software

Lead developer · Software engineer and geographic information systems (GIS)

Designed and built from scratch as a professional desktop application for the analysis and bulk processing of ground-penetrating radar (GPR) data. It modernizes pavement and linear-infrastructure surveys — roads and Formula 1 circuits — by combining physical signal processing with interactive geospatial visualization.

Gallery

The challenge

GPR surveys produce huge volumes of data: .rad files made of thousands of traces and samples. Traditional analysis forced each line to be processed on its own, in legacy software that was hard to use and disconnected from geography. The goal was a scalable, responsive tool that could inspect tens of kilometres at once and match subsurface dielectric anomalies with their GPS position in real time.

Solution architecture

To keep the interface responsive with large data matrices, the engine is separated from the view and each layer has a single responsibility:

  • Processing engine. A Python backend that manages multi-line memory, applies mathematical filters with SciPy and NumPy, and stores the interpreted structural layers.
  • Presentation and controllers (PyQt6). Independent controllers for the editor and the map react to engine state. Business logic stays out of the view.
  • Bidirectional GIS bridge. An embedded web view injects dynamic HTML and JavaScript with Folium and Leaflet, and talks to the desktop application through web channels.

Innovations

  • Batch multi-line processing. Several radar sections are loaded and drawn asynchronously, without freezing the interface.
  • Bidirectional spatial sync. The radargram and the GIS map stay linked. Moving the cursor over a wave updates a map marker, and the reverse, so a subsurface anomaly can be placed on the alignment.
  • Smart picking. Automatic detection of dielectric interfaces from the wave centre or amplitude peaks, used to fill in asphalt-layer thickness.
  • GIS-style layer manager. A visibility tree with an exclusive edit mode and a concurrent view mode. Technicians show, hide and reorder profiles of different physical layers.

Technology stack

  • Python 3.10+
  • PyQt6 (interface and event architecture)
  • NumPy and SciPy (time-zero, exponential gain and band-pass filters)
  • Folium / Leaflet (interactive maps and heat maps)

Corporate development under confidentiality. The source code is not published.

Impact

Layer processing and marking, previously done line by line, is now handled in one place. Dielectric-constant heat maps and critical-point detection support predictive maintenance of demanding infrastructure.
